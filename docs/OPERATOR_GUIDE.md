# Inside Access — founder guide (v0.6.4)

**Your three areas: Inbox, Listings, System.** Use your existing login. Nothing is automatically approved or published.

## A normal review session

1. **System → Run discovery.** First time only, read and acknowledge the linked source terms, then enable Paris. Later, simply Run discovery. Keep the app/computer running for local daily checks. A source error is a retry/review task; it never authorizes publication.
2. **Inbox.** Review new discoveries, proposed source changes, verification problems and exceptions. Open Review on a listing. Source changes have their own apply/dismiss decision; applying creates an unverified draft.
3. **Check the source and access route.** Use the source/booking links. Correct facts using Core, Dates, Access or Evidence and Save changes. Leave unknown facts unknown. Editing a listing revokes its previous approval/publication.
4. **Approve for publication**, then **Publish listing**. These remain separate actions. Ordinary notes are optional. Rejection and warning overrides require a reason. A disabled button explains what is missing; hard verification/eligibility/date blockers cannot be bypassed.
5. **Images.** Preview privately, confirm the specific event and actual reuse/direct-embedding permission with evidence and credit, then independently approve the image. Listing publication does not approve an image. Unknown rights keep the fallback.

## Find or remove a listing

**Listings** has one searchable database. More filters includes city, verification, approval, original queue and lifecycle. Expired archive keeps ended records, rather than deleting them. Use More filters for closed/cancelled/sold-out statuses. Reopen for review is reversible but does not make old dates current: correct/reverify facts before publication. Unpublish removes public visibility immediately. Original IDs/history remain.

## A short weekly check

Open **System**. Check last successful discovery and source errors. Retry a failed source; use Source watchlist for settings. Create verified backup, then Download latest full backup to a protected location separate from this computer. Automatic daily backups happen while the local app runs; a local disk copy alone does not protect against losing that disk. Actual billing is not connected; keep service usage below the documented free allowances.

**Starting locally:** after the one-time update, double-click Start_Inside_Access.command in your existing app folder. It opens the browser without commands to type. Keep its window open; closing the app or switching the Mac off stops local operations. Native macOS launcher execution still needs checking on your Mac. Managed cloud operation removes this dependency only after the separate approved setup.

**Ask for technical help only for:** the one-time update/cloud setup, account permissions, a failed backup/restore or an application update. Daily review, discovery, publishing, unpublishing, image decisions, exports and backup downloads work in the browser. Never recreate your account or restore a starter database over your current installation.
